## 工作负载结果

以下是每种模式 3 轮的吞吐中位数和各轮 P99 的中位数。API 时延使用单操作墙上时间；CPU 为整个进程 user+system 除墙钟时间，100% 表示一个逻辑核；RSS 为整个进程峰值，磁盘为最终 DB 文件字节，不是峰值。每轮独立数据库，seed 42、4 线程、200 key、128 字节值。不同版本测试不交错，存在系统负载差异。`sync=0` 的确认没有逐笔 fsync 保证，不能与 `sync=1` 当成相同持久化语义。

| 模式、工作负载 | 基线 2318bb6 Ops/s / P99 µs | 当前 6a94f1d Ops/s / P99 µs |
|---|---:|---:|
| sync=0 顺序 Put | 893,850.75 / 2.20 | 844,751.56 / 3.09 |
| sync=0 随机 Get | 632,663.13 / 1.91 | 1,040,680.19 / 0.87 |
| sync=0 范围 Scan（最多 16 条） | 48,608.91 / 24.69 | 9,813.87 / 112.59 |
| sync=1 顺序 Put | 500.09 / 2,113.72 | 499.92 / 2,121.58 |
| sync=1 范围 Scan（最多 16 条） | 49,200.98 / 25.41 | 9,859.84 / 106.38 |

范围扫描在此小样本中明显退化；它不能代表所有场景，也不应宣称此版本全面加速。`workloads_final_20261116/summary.csv` 有所有阶段的每轮数据以及 CPU、内存、磁盘统计。每次 Flush、Compaction、关闭、重开每轮只有一个样本，其百分位就是该单次观察值。

各轮均观察到 1 次全量 Compaction、输出 57,239 字节、后台未完成槽峰值为 1（**包括正在执行的任务**，不是仅等待队列的长度）；耗时和 cache 命中数在每轮 `stats.json`。同步模式 Compaction 时间依轮次约 9.928–10.044 ms；该数包含实现中的提交和清理范围，不是仅 SST 编码时间。

针对扫描的后续诊断发现：旧实现会将不在范围的活动 MemTable 键也复制到临时 map，300 个无关键使测试扫描的分配次数由 232 增到 832；`6a94f1d` 按边界合并后都是 232 次，且覆盖 immutable 和 active 中同键更新的回归通过。固定 200 个 SST 键、200 个无关活动键、5000 次扫描的单独测试按前后/后前/前后交替三轮，`975c0e7` 为 589/590/592 ms，`6a94f1d` 为 507/508/531 ms；两者 GCC `-O3 -DNDEBUG`，共享机器，CPU 与 OS 缓存未隔离。这个结果仅支持该小样本优化，不与上表基线构成完整或稳态对照。完整命令、数据与程序在 `scan_pair_20261116/`，红绿测试在 `scan_bounds_*_20261116.txt`。SST 块索引仍需在每次扫描时解析，不能认为所有扫描退化已经消除。

独立的 `stonekv_io_profile` 额外包装直接系统调用，`1afcb01` 版本 6 轮均读取 `pread` 721,130 字节、写入 `write/pwrite` 270,293 字节；返回 key/value 261,273 字节、逻辑变更 key/value 99,350 字节，得到约 2.760 倍读取系统调用字节比、2.721 倍写入系统调用字节比。统计包含整个工作负载的恢复和维护；MANIFEST 通过 C++ 流读取不在 `pread` 数内，故读取数只是已拦截调用的下界。页面缓存、文件系统元数据和设备物理 I/O 不在范围，仪表化计时不用于吞吐比较。原始 JSON 在 `workloads_ioprofile_20261116/`，口径及复现见 `docs/BENCHMARK.md`。

## 限制与待办

- 实验不是工业生产成熟度或断电可靠性证明；旧 WAL 格式和不完整尾部有上文所述固有限制。
- 进程级随机 SIGKILL 和单次随机 ENOSPC/EIO/fsync 注入仍未覆盖所有故障组合、文件系统和真实设备故障；线程安全需要可用环境下的 TSan 进一步验证。
- 当前扫描及小数据集尾延迟退化；V3 打开时全量校验，Compaction 会临时生成全 key 索引，尚需分析大数据集的峰值内存和持续性能。
- 缺少 RocksDB/LevelDB 相同工作负载、相同持久化条件的对照；无证据支持性能倍数。也未做充分的大数据量长期压力测试。
- GitHub 远端 PR、Actions 结果以实际推送运行情况为准；不能凭本地 CTest 冒充远端 CI。
